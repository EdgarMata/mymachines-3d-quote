# Roadmap — MVP release gates

## Now: secure the private MVP
Work locally, use small tested changes, then request approval for commit/push and private deployment updates.

1. MM-001 — Secure STL Upload Validation: implemented and locally verified. Shared extension, empty-file and bounded-read checks protect all four endpoints. The default file limit is 50 MiB with validated configuration; the complete request limit is 51 MiB, aligned with Nginx and enforced during reception even without Content-Length. Client filenames are display metadata only. Tests cover exact boundaries, oversize rejection, malicious names and multipart cleanup after interrupted reception. MM-002 adds geometry/parameter checks and generic processing errors; a full response allowlist review remains pending. No deployment is implied by completion of this source change.
2. MM-002 — Geometry and Printing Parameter Validation: implemented, reviewed and tested; not deployed. Shared binary/ASCII structural preflight and finite usable geometry checks; configurable 1,000,000-facet limit; finite rotations; configurable quantity maximum (default 100, minimum 1); material/quality pair checks. A validated mesh is reused for orientation. Non-watertight models with usable surface remain allowed; automatic pricing requires valid positive slicing time and material mass. Extreme finite coordinates use overflow-safe merging and checked binary export. Synthetic regression tests and real binary/ASCII OrcaSlicer estimates cover the new path. See architecture for acceptance policy and known limits.
3. MM-003 — Processing Concurrency and Slicer Timeouts: implemented and reviewed; not deployed. Pre-parser admission defaults to one heavy request with no queue; busy requests get 503 / Retry-After 5. Bounded worker threads keep the event loop available and retain leases after cancellation until actual completion. Slicer deadline defaults to 60 seconds, with process-group kill/reaping and safe 504 responses. One Uvicorn worker and Nginx 90-second read allowance are explicit. No total request/geometry deadline or distributed concurrency gate is introduced; assess these separately before scaling. Final review adds bounded stdout/stderr capture and verifies atomic lease transitions, process-group isolation and failure recovery. Frontend error tests run in the CI matrix. See architecture/deployment for cancellation and process-group limitations.
4. MM-004 — Temporary File Lifecycle and Cleanup: implemented and reviewed; not deployed. Preserves immediate TemporaryDirectory cleanup and MM-003 cancellation/process ownership. Shared versioned workspaces, sibling ownership metadata and file locks support startup/periodic recovery; inherited slicer locks protect surviving children after backend exit. Defaults: orphan eligibility after 3600 seconds, sweep interval 300 seconds. Eligibility is not a maximum retention deadline; active work is always skipped. Slicer home/XDG/system-temp outputs stay inside its workspace; no model/G-code archive, generic /tmp sweep, persistent volume or dependency is added. Existing framework/Nginx automatic cleanup is preserved. Final review revalidates opened metadata after locking, rejects short identity writes before processing, and tests creation phases, descriptor release and app lifespan responsiveness. See temporary-storage documentation for inventory, permission/legacy/crash-window limits and normal unlink semantics. Hard disk quotas and real deployment storage/load validation remain pending.
5. MM-005 — Public API Contracts and Internal Data Protection: implemented and reviewed; not deployed. Nested Pydantic response allowlists cover all seven business/diagnostic endpoints, including optional legacy routes. Raw slicing costs/profile names, internal paths/readiness flags and future unknown fields stay internal. Existing price/selection/status/UI behavior is preserved. Controlled request/response/HTTP errors avoid input/context/raw-exception echo; diagnostics retain route/type only. Production Compose explicitly selects production defaults: legacy routes and Swagger/ReDoc/OpenAPI disabled, cross-origin access empty. Development utilities and local Vite origins remain available; overrides are validated. Final review preserves Retry-After for generic 503 errors and adds route/list/null/optional-field checks plus local production-mode HTTP smoke tests. Browser-control access was unavailable; real-browser functional approval remains pending. See [API contracts](API_CONTRACTS.md) for exact fields, audit, manual steps and limitations. Schema hiding/CORS are not authentication, and response filtering does not prevent cost inference from public prices.
6. MM-006 — Abuse protection and rate limiting: implemented and final-reviewed; not deployed. Native frontend Nginx per-IP rates/bursts, five active API requests/IP, global rate/active-request budgets and controlled JSON 429. Exact trusted immediate peers may supply canonical X-Real-IP; arbitrary forwarded headers cannot rotate budgets. Default direct mode trusts none; production requires a private operator allowlist and fails on empty/broad trust. Receive inactivity/header/keepalive controls preserve buffering, byte limits and MM-001–005 behavior. Frontend handles 429 with manual retry. Native proxy-chain/abuse tests are integrated into both existing CI architecture jobs; the maintainer confirms successful MM-006 native AMD64/ARM64 CI. See [Abuse protection](ABUSE_PROTECTION.md). Actual NPM peer/header/edge controls, browser approval and real-load deployment verification remain pending.
7. MM-007 — Private commercial configuration: implemented and final-reviewed; not deployed. A strict, complete versioned JSON snapshot is validated before startup. Production requires an explicit private external file and rejects bundled demo selection; development retains unchanged demo results. Backend-only read-only mount, no dynamic reload, safe diagnostics and per-operation Orca filament-cost override preserve the existing algorithm/profiles. Public build-input allowlists, synthetic context/image/startup/API tests and both native CI jobs protect against accidental inclusion. Final review adds finite intermediate/result checks without monetary caps and same-image synthetic Docker update/rollback with atomic replacement. See [Commercial configuration](COMMERCIAL_CONFIGURATION.md). Operator price approval, private rollout/backup/rollback and real browser/load validation remain pending. MM-008A local validation is documented below; no deployment is implied.

8. MM-008A — Load, Security and Resilience Validation: opt-in bounded local Docker harness and private evidence collection; no production feature or architecture changes. See [Load and resilience testing](LOAD_AND_RESILIENCE_TESTING.md) for progressive scenarios, safety stops and limitations. Final review confirms the descriptor fix, preserved binary/ASCII output and private evidence exclusion. READY WITH CONDITIONS is accepted for future private validation, not public exposure. The [MM-008B command runbook](MM008B_PRIVATE_VALIDATION.md) is prepared only. Large-model capacity, temporary storage, continuously slow uploads and the unexplained isolated 502 require evidence-based release decisions. MM-008B execution and public exposure remain subject to explicit approval.

All numerical limits above are provisional engineering proposals, not approved commercial policy. Validate representative real models and simultaneous requests; adjust with maintainer approval.

## Next: release and deployment
- Resolve applicable third-party license, source availability and resource provenance requirements. Public source availability alone is not a complete binary distribution audit.
- Publish approved multi-architecture images to GHCR, verify manifests and immutable commit tags. Improve traceability between tested and released images as needed.
- Automate deployment with least-privilege credentials, verified SSH host keys, serialized releases, health checks and rollback by immutable tag. Docker access is privileged. Never expose deploy secrets to untrusted PR jobs.
- Validate private ARM64 deployment, resource usage under realistic load, service isolation and restart/recovery. Confirm no adverse effect on other hosted services.
- Configure public DNS, reverse proxy, TLS, upload/timeouts and rate limits only after maintainer approval. Verify externally; provide a visible source/license link as applicable.

## Technical debt and remaining validation
- Existing frontend lint failure: `react-hooks/set-state-in-effect` in the model-analysis effect of `frontend/src/App.tsx`. Reproduced from the pre-MM-003 `HEAD`; resolve in a focused viewer/state refactor without disabling lint rules. It is unrelated to concurrency/timeout error handling.
- MM-006 limits ingress rates/active requests and inactive uploads, but continuously slow bodies can occupy slots indefinitely. NPM may buffer before frontend controls apply; actual edge controls require deployment review. Partial-header attacks, NAT/shared budgets, IPv6 rotation, multi-instance budgets and distributed starvation remain limitations. No absolute upload deadline, disk quota, authentication or DDoS guarantee is added.
- No hard total request or geometry-processing timeout. Cancellation cannot forcibly stop a Python worker thread.
- Admission is local to one Uvicorn process; multiple workers/replicas require a separately designed shared limit.
- Representative resource/latency/load validation on the shared ARM64 VPS remains pending explicit deployment/test approval. Local synthetic tests are not a production load benchmark.
- MM-004 recovery intentionally leaves unrecognized/legacy folders and incomplete or mismatched metadata for approved operator review. Permission failures can postpone deletion; retention is not a disk quota or secure erasure guarantee. A crash before ownership metadata is complete can leave an unrecognized directory. Proxy buffering and active slicer output still need realistic disk-use validation.
- MM-005 intentionally exposes public machine IDs/labels/volumes, compatibility outcomes and final prices. Necessary review outcomes may imply availability; hiding raw flags does not hide that behavior. Public-labelled configuration must contain public data. Server/proxy access-log query/IP retention/redaction needs deployment review; API diagnostics omit exception payloads. CORS and hidden docs provide no authorization boundary.
